# GitHub Integration 使用指南

## 概述

本系统支持与 GitHub CI/CD 集成，实现：
- PR 打开/更新时自动生成测试用例
- 自动执行测试并生成报告
- 在 PR 下自动评论测试结果
- GitHub Actions 工作流

## 快速开始

### 1. 配置环境变量

```bash
cp .env.example .env
```

编辑 `.env` 文件：

```env
# GitHub Personal Access Token (必须)
GITHUB_TOKEN=ghp_xxxxxxxxxxxx

# Webhook 签名密钥 (可选)
GITHUB_WEBHOOK_SECRET=your-secret
```

### 2. 获取 GitHub Token

1. 访问 https://github.com/settings/tokens
2. 点击 "Generate new token (classic)"
3. 选择权限：
   - `repo` (完全控制)
   - `workflow` (管理 GitHub Actions)
4. 复制生成的 token

### 3. 配置 GitHub Actions (推荐)

在你的项目根目录创建 `.github/workflows/ai-test.yml`：

```yaml
name: AI Auto Test

on:
  pull_request:
    types: [opened, synchronize]

env:
  TEST_API_URL: ${{ secrets.TEST_API_URL }}
  TEST_API_KEY: ${{ secrets.TEST_API_KEY }}

jobs:
  ai-test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - name: Trigger AI Test
        run: |
          curl -X POST "$TEST_API_URL/api/v1/github/trigger" \
            -H "Content-Type: application/json" \
            -H "Authorization: Bearer $TEST_API_KEY" \
            -d '{"repo_name": "${{ github.repository }}", "pr_number": ${{ github.event.pull_request.number }}'
```

### 4. 配置 Secrets

在 GitHub 仓库 Settings → Secrets and variables → Actions 中添加：

| Secret Name | Description |
|-------------|-------------|
| `TEST_API_URL` | 你的测试 API 地址 |
| `TEST_API_KEY` | API 认证密钥 |

## API 端点

### Webhook 端点

```
POST /api/v1/github/webhook
```

GitHub 发送的 Webhook 事件：
- `pull_request`: PR 创建/更新
- `push`: 代码推送
- `check_run`: CI 检查完成

### 手动触发

```
POST /api/v1/github/trigger
```

```json
{
  "repo_name": "owner/repo",
  "pr_number": 123,
  "github_token": "ghp_xxx"
}
```

## 本地测试

```bash
# 启动服务
python main.py

# 手动触发测试
curl -X POST "http://localhost:8001/api/v1/github/trigger" \
  -H "Content-Type: application/json" \
  -d '{
    "repo_name": "your-username/your-repo",
    "pr_number": 1,
    "github_token": "ghp_xxx"
  }'
```

## 注意事项

1. **Rate Limiting**: GitHub API 有速率限制，注意控制请求频率
2. **Token 权限**: 确保 Token 有 `repo` 和 `workflow` 权限
3. **Webhook 安全**: 生产环境建议启用签名验证
4. **并发控制**: 避免同一 PR 的重复测试触发
